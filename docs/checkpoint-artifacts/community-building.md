### What we did and why
We focused on making GradEval360 easier for new contributors to understand and participate in. As a greenfield project, most contributor friction happens at the start: getting local setup right, figuring out where to begin, and understanding how work is organized. We updated `CONTRIBUTING.md` to clarify the onboarding sequence (setup, code of conduct, and architecture overview), added guidance on issue labels, and documented expectations for pull requests. We also created GitHub issue and PR templates to make incoming contributions more consistent and reduce back-and-forth during review.

### Who this advances and how
This activity primarily advances the **contributor community**. New contributors now have a clear path to get started, standardized templates for issue reporting and feature requests, and a checklist for PR submission. These changes make the project more approachable and reduce the hidden knowledge required to contribute effectively.

### Observed response or impact
The immediate impact is improved readiness for onboarding: the repository now contains the minimum infrastructure that external contributors typically expect. The templates also encourage higher-quality issues and PRs, which should reduce review overhead and improve the signal in the backlog.

### What we learned about our community needs
In a greenfield project, community-building is less about outreach and more about **removing friction**. Contributors need clarity on how to start, what “good” looks like, and where their work fits into the project. Documenting labels and expectations early is essential because it prevents confusion as the issue list grows.

### How this advances our community strategy
These changes establish a baseline contributor experience and set the groundwork for scaling community involvement as the project matures. The contribution path and templates are now stable enough to support upcoming outreach, contributor recruiting, and future “good first issue” work.

### Next steps
- Create a small set of curated `good first issue` tickets tied to onboarding-friendly tasks.
- Add a short “Contributor Quickstart” in the README for faster discovery.
- Collect feedback from first-time contributors to refine the templates and onboarding steps.
